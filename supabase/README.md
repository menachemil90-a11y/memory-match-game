# Supabase backend (online 1v1)

Server-authoritative online play. Clients can only **read** their own room
(RLS); every move goes through `SECURITY DEFINER` functions that apply the same
rules as the app's TypeScript engine. The shuffled deck lives in the `private`
schema, which the API never exposes.

| File                                      | What                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `migrations/…_online_core.sql`            | Tables, RLS, API functions (`create_room`, `join_room`, `flip_card`, `resolve_turn`, `claim_timeout`, `heartbeat`, `claim_disconnect_win`, `leave_room`, `request_rematch`, `server_time`), secure shuffle with no-repeat history, nickname filter, `min_supported_version`   |
| `migrations/…_builtin_boards.sql`         | Generated by `node scripts/gen-board-seed.mjs` — image ids the server deals from                                                                                                                                                                                              |
| `migrations/…_cleanup_cron.sql`           | pg_cron job removing stale rooms every 15 minutes                                                                                                                                                                                                                             |
| `migrations/…_anonymous_user_cleanup.sql` | Daily deletion of anonymous users inactive for 30 days (data minimisation)                                                                                                                                                                                                    |
| `migrations/…_harden_table_grants.sql`    | Removes the write privileges a real Supabase project grants to `anon`/`authenticated` by default (tables stay read-only for the API), indexes `rooms.level_id`                                                                                                                |
| `migrations/…_photo_rooms.sql`            | Online games on the host's photo board: `preparing` rooms, private `room-photos` bucket + Storage RLS (host uploads, the two players read, 24 h cap), `create_photo_room`, `photo_room_ready`, `expired_room_photos` (service role only), pg_cron → Edge Function every 5 min |
| `functions/room-photos-cleanup/`          | Edge Function: deletes the cards of closed/vanished rooms and anything older than 24 h through the Storage API (deployed with JWT verification off; it only deletes what is already due)                                                                                      |
| `tests/`                                  | `npm run test:server` — runs the migrations on a real Postgres (PGlite) and proves server = engine with randomized parity games                                                                                                                                               |

## Deploying (one-time)

1. Create a Supabase project (free tier is enough to start).
2. Apply the migrations in order (`supabase db push`, or the SQL editor).
3. **Authentication → Sign In / Providers → enable "Allow anonymous sign-ins".**
   Recommended: turn on CAPTCHA protection for anonymous sign-ins later.
4. Put the project URL and **anon** key into `.env` (committed; see `.env.example`) and rebuild.
   Only these two public values belong in the repository — never the `service_role` key, a
   secret key (`sb_secret_…`), the database password or an access token.

### Photo rooms (migration 06) — deploy steps

1. **Edge Function first:** deploy `functions/room-photos-cleanup` with **JWT verification
   off** (`supabase functions deploy room-photos-cleanup --no-verify-jwt`, or dashboard →
   Edge Functions → Deploy a new function → paste `index.ts` → turn off "Verify JWT").
2. **Then paste** `migrations/20261119000006_photo_rooms.sql` in the SQL Editor (it creates
   the bucket, the policies, the functions and the 5-minute cron job; it enables `pg_net`).
3. Check: Storage shows a **private** bucket `room-photos`; `select * from cron.job` lists
   `memory-match-delete-room-photos`.

The migration hard-codes this project's Edge Function URL in the cron job (public value).

### Applying a new migration

Supabase dashboard → SQL Editor → New query → paste the whole file → Run. Apply files
in order, each exactly once. Afterwards ask Claude to re-verify (read-only).

## Operating

- Force an app update for online play:
  `update public.app_config set value = '"1.2.0"' where key = 'min_supported_version';`
- Turn timer / disconnect grace: keys `turn_seconds`, `disconnect_grace_seconds`.
