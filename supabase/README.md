# Supabase backend (online 1v1)

Server-authoritative online play. Clients can only **read** their own room
(RLS); every move goes through `SECURITY DEFINER` functions that apply the same
rules as the app's TypeScript engine. The shuffled deck lives in the `private`
schema, which the API never exposes.

| File                              | What                                                                                                                                                                                                                                                                        |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `migrations/…_online_core.sql`    | Tables, RLS, API functions (`create_room`, `join_room`, `flip_card`, `resolve_turn`, `claim_timeout`, `heartbeat`, `claim_disconnect_win`, `leave_room`, `request_rematch`, `server_time`), secure shuffle with no-repeat history, nickname filter, `min_supported_version` |
| `migrations/…_builtin_boards.sql` | Generated by `node scripts/gen-board-seed.mjs` — image ids the server deals from                                                                                                                                                                                            |
| `migrations/…_cleanup_cron.sql`   | pg_cron job removing stale rooms every 15 minutes                                                                                                                                                                                                                           |
| `tests/`                          | `npm run test:server` — runs the migrations on a real Postgres (PGlite) and proves server = engine with randomized parity games                                                                                                                                             |

## Deploying (one-time)

1. Create a Supabase project (free tier is enough to start).
2. Apply the migrations in order (`supabase db push`, or the SQL editor).
3. **Authentication → Sign In / Providers → enable "Allow anonymous sign-ins".**
   Recommended: turn on CAPTCHA protection for anonymous sign-ins later.
4. Put the project URL and **anon** key into `.env` (committed; see `.env.example`) and rebuild.
   Only these two public values belong in the repository — never the `service_role` key, a
   secret key (`sb_secret_…`), the database password or an access token.

## Operating

- Force an app update for online play:
  `update public.app_config set value = '"1.2.0"' where key = 'min_supported_version';`
- Turn timer / disconnect grace: keys `turn_seconds`, `disconnect_grace_seconds`.
